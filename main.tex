% Introduction

\posterblock{Introduction}{
  LLMs differ in capability, price, speed, and task
  specialization. Benchmark leaders are not always
  the best choice for a user's budget or workflow.

  \vspace{0.20em}
  \textbf{LLM Picker} combines performance data,
  task rankings, and community discussion to make
  model trade-offs visible.
}

% Research questions

\posterblock{Research Questions}{
  \begin{itemize}\tightitems
    \item Which models offer the best
      \textbf{capability--cost and capability--speed}
      trade-offs?

    \item Which models best fit Agent, Document,
      Search, or WebDev tasks, at what cost?

    \item What additional context comes from
      real community discussions?
  \end{itemize}
}

% Datasets

\posterblock{Datasets}{
  \begin{itemize}\tightitems
    \item \textbf{Artificial Analysis:}
      Intelligence, Coding, and Agentic indices;
      token prices, task cost, and inference speed.

    \item \textbf{LMArena:}
      Agent, Document, Search, and WebDev
      leaderboards and ratings.

    \item \textbf{Hacker News / Algolia:}
      recent stories, hierarchical comments,
      and reviewed provider/model mentions.
  \end{itemize}
}

% Methods and implementation

\posterblock{Methods and Implementation}{
  \begin{itemize}\tightitems

    \item \textbf{Data ingestion:}
      Fetch paginated AA v2 API data,
      latest LMArena task leaderboards from
      Hugging Face, and Hacker News stories
      with nested comments via Algolia.

    \item \textbf{Cleaning and matching:}
      Use AA UUIDs for identity;
      normalize model names with NFKC
      and reviewed aliases.
      Preserve reasoning variants,
      remove duplicate rankings,
      and treat missing measurements
      as \texttt{NULL}.

    \item \textbf{Derived measures:}
      Find Pareto-efficient models for
      capability against cost or speed.
      Compute per-task ranks,
      model-card percentiles,
      and stacked task-cost components
      proportional to published token prices.

    \item \textbf{Visualization and interaction:}
      D3/SVG renders scatterplots,
      parallel axes, rank charts, bars,
      heatmaps, radar profiles,
      and comment trees.
      Linked brushing, filters, sorting,
      and three-model pinning
      support comparison.

    \item \textbf{Architecture and QA:}
      React manages linked views;
      Django REST/SQLite serves
      data and provenance.
      Celery Beat/Redis updates
      benchmarks twice daily and
      discussions hourly,
      with automated pipeline tests.

  \end{itemize}
}

% Key insights

\posterblock{Key Insights}{
  \begin{itemize}\tightitems
    \item Several affordable models remain
      \textbf{Pareto-efficient}, even when
      they do not have the highest benchmark
      score.

    \item Speed and cost produce
      \textbf{different trade-offs}.

    \item Task leaders vary across
      categories; Document and Search
      have much sparser evaluation coverage.

    \item Community discussions reveal
      comparison contexts missing
      from benchmark tables.

    \item Strong capability often comes with
      lower affordability or slower response.

    \item Linked views turn broad rankings
      into task-specific model shortlists.
  \end{itemize}
}

% Conclusions

\posterblock{Conclusions}{
  \begin{itemize}\tightitems
    \item Benchmarks and prices are
      \textbf{snapshots}, not guaranteed
      real-world performance or individual
      token bills.

    \item Cross-source model matching
      and unequal category coverage limit
      comparisons; forum mentions
      do not imply approval.

    \item Next: historical trends,
      uncertainty, user-defined workloads,
      and more accessible color scales.
  \end{itemize}
}
